# Team architecture handbook

Start with [the selected decisions and why they fit](selected-decisions.md), then read [the plain-English build guide](plain-english-build-guide.md). Use [work packages](team-work-packages.md) to assign people and [data/metric rules](data-and-metric-rules.md) to agree the calculations.

This folder is a self-contained team handout. It describes the required behavior, boundaries, inputs, outputs and acceptance checks for an independent build. It contains no application source filenames, implementation class names, repository history or private branch references.

Suggested reading order:

1. Everyone reads the product journey, agent descriptions and shared rules.
2. Each owner reads their component and relevant workflow nodes.
3. Producers and consumers agree the shared records and failure states.
4. The integration owner assigns names to work packages and checks the full journey.

The documents are design requirements, not a claim that the new team's implementation is complete.
